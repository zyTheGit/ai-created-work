## 三、详细学习路线

### Phase 1：低代码引擎核心（第 1-4 个月）

#### 3.1 Schema 设计与渲染引擎

```
核心概念：
Schema = 数据结构描述（JSON）
渲染引擎 = Schema → UI 的转换器

Schema 设计原则：
├── 声明式 — 描述"是什么"，不是"怎么做"
├── 可组合 — Schema 可以嵌套组合
├── 可扩展 — 支持自定义组件和属性
├── 版本化 — Schema 有版本号，支持迁移
└── 可序列化 — 纯 JSON，可存储、可传输

Schema 示例：
{
  "version": "1.0",
  "type": "FormPage",
  "props": {
    "title": "用户信息",
    "layout": "vertical"
  },
  "children": [
    {
      "type": "Input",
      "props": {
        "label": "姓名",
        "field": "name",
        "required": true,
        "maxLength": 50
      }
    },
    {
      "type": "Select",
      "props": {
        "label": "部门",
        "field": "department",
        "dataSource": "/api/departments"
      }
    }
  ]
}

渲染引擎核心逻辑：
1. 解析 Schema → 构建组件树
2. 递归渲染 → 每个节点映射到对应组件
3. 数据绑定 → field 属性关联表单数据
4. 事件处理 → 统一的事件分发机制
5. 校验聚合 → 收集所有字段的校验规则
```

### Phase 3：AI 智能化增强（第 9-14 个月）

#### 3.1 AI 生成 Schema

```
核心场景：
用户用自然语言描述 → AI 生成表单/页面 Schema → 人工调整 → 渲染

实现路径：
┌──────────────────────────────────────────┐
│ 用户输入                                  │
│ "创建一个员工入职登记表，包含姓名、性别、  │
│  身份证号、部门、职位、入职日期、紧急联系人"│
└──────────────┬───────────────────────────┘
               ↓
┌──────────────────────────────────────────┐
│ AI 处理                                   │
│ 1. 解析用户意图                           │
│ 2. 识别字段类型（姓名→Input, 性别→Radio） │
│ 3. 推断校验规则（身份证→pattern）          │
│ 4. 推断数据源（部门→Select+API）          │
│ 5. 生成完整 Schema                        │
└──────────────┬───────────────────────────┘
               ↓
┌──────────────────────────────────────────┐
│ 输出 Schema                               │
│ {                                         │
│   "type": "FormPage",                     │
│   "props": { "title": "员工入职登记" },    │
│   "children": [                           │
│     { "type": "Input", "props": {         │
│       "label": "姓名", "field": "name",   │
│       "required": true                    │
│     }},                                   │
│     { "type": "Radio", "props": {         │
│       "label": "性别", "field": "gender", │
│       "options": ["男", "女"]             │
│     }},                                   │
│     ...                                   │
│   ]                                       │
│ }                                         │
└──────────────────────────────────────────┘
```

#### 3.3 AI 辅助逻辑编排

```
场景：
用户描述业务逻辑 → AI 生成逻辑编排配置 → 可视化展示 → 人工调整

示例：
用户："当金额超过 10000 时，需要部门经理审批"
AI 生成：
{
  "type": "Condition",
  "condition": { "field": "amount", "op": ">", "value": 10000 },
  "then": {
    "type": "Approval",
    "approver": "department_manager"
  }

```

#### 3.4 AI 辅助数据查询

```

{
  "timeRange": "last_month",
  "conditions": [
    { "field": "sales_amount", "op": ">", "value": 100000 },
    { "field": "region", "op": "=", "value": "华东" }
  ],
  "groupBy": "customer_name"

```

## 四、对标分析

### 业界参考

| 项目 | 特点 | 学习点 |
|------|------|--------|
| **Formily** | 阿里出品，最成熟的表单方案 | Schema 设计、联动系统、路径系统 |
| **Amis** | 百度出品，JSON 驱动的 UI 框架 | Schema 渲染、组件体系、数据映射 |
| **LowCodeEngine** | 阿里出品，低代码引擎标准 | 编辑器架构、插件体系、物料协议 |
| **FormRender** | 阿里出品，JSON Schema 表单 | Schema 到表单的映射、校验系统 |
| **Vue Form Making** | 基于 Vue 的表单设计器 | 拖拽交互、属性编辑、代码生成 |

### 学习策略

```
1. 深度阅读 Formily 源码
   - 理解其 Schema 设计哲学
   - 理解其联动系统实现
   - 理解其路径系统（Path）

2. 分析 Amis 的 JSON Schema 规范
   - 学习其组件类型定义
   - 学习其数据映射机制
   - 学习其表达式系统

3. 参考 LowCodeEngine 的架构
   - 学习其插件体系设计
   - 学习其物料协议
   - 学习其编辑器架构

4. 结合 PMS 组件库
   - 将学习成果与 PMS 组件库结合
   - 设计兼容 PMS 的 Schema 规范
   - 实现基于 PMS 组件的渲染器
```
