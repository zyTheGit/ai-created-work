# AI 协作开发学习路线

> 优先级：⭐⭐⭐ 最高
> 时间投入：0-3 个月，每天 1 小时
> 目标：从"写代码的人"变成"用 AI 审代码的人"，开发效率提升 50%+

---

## 一、为什么这是最高优先级

1. **立竿见影**：学会用 AI 工具，当天就能提升效率
2. **保命技能**：不会用 AI 的前端工程师，1 年后会非常被动
3. **基础前提**：后续的 AI 应用开发能力，建立在对 AI 工具的熟练使用上

---

## 二、学习路线

### Phase 1：AI 编码工具精通（第 1-2 周）

#### 2.1 Claude Code（当前首选）

**学习目标**：熟练使用 Claude Code 完成日常开发任务

| 能力项 | 学习内容 | 验收标准 |
|--------|----------|----------|
| 基础交互 | 会话管理、上下文控制、文件操作 | 能用自然语言完成日常编码 |
| 高级 Prompt | 精确描述需求、约束条件、上下文 | AI 输出可用率 > 80% |
| 项目配置 | CLAUDE.md、Rules、Memory | 项目配置完善，AI 理解项目上下文 |
| Hook 与自动化 | Pre/Post hooks、自定义命令 | 实现自动 lint、自动测试 |
| 多模式协作 | Plan 模式、Agent 模式 | 复杂任务先规划再执行 |

**实践练习**：
```
1. 用 Claude Code 从零搭建一个 Vue3 + TS 项目
2. 配置 CLAUDE.md 让 AI 理解你的项目规范
3. 用 AI 完成一个完整功能（页面 + 接口 + 测试）
4. 体验 Plan 模式：先让 AI 出方案，再执行
```

#### 2.2 Zed 编辑器（AI 辅助编码）

**学习目标**：掌握 Zed 编辑器中 Agent 面板和 AI 功能的高效用法

| 能力项 | 学习内容 | 验收标准 |
|--------|----------|----------|
| Agent 面板 | 对话交互、上下文管理、工具权限 | 能通过 Agent 面板完成跨文件修改 |
| Inline Assist | 行内 AI 编辑、接受/拒绝 | 能快速修改小段代码 |
| 上下文服务器 | MCP Server 配置（context7 等） | 配置完成并能查询文档 |
| 模型切换 | 多模型配置（DeepSeek/Qwen/MiMo） | 能根据场景选择合适模型 |
| AGENTS.md | 项目级 Agent 行为配置 | 项目级 AI 行为定制 |

**Zed 当前配置要点**：
- Agent 服务器：claude-acp（Node v24.14.1 via fnm）、opencode
- 上下文服务器：mcp-server-context7（带 API Key）
- 默认模型：deepseek-v4-flash（思考模式，高投入）
- 备选模型：MiMo（mimo-v2-pro）、Qwer（qwen3.6-plus/qwen3-max/glm-5/kimi-k2.5）
- LSP：vtsls（TypeScript/JavaScript）
- 格式化：ESLint 自动修复 → Prettier
- 终端：Git Bash

#### 2.3 Claude Code + Zed 协同工作流

**学习目标**：建立 Claude Code（终端）+ Zed（编辑器）的高效协同模式

```
协同工作流：
┌────────────────────────────────────────────────┐
│ Zed 编辑器                                      │
│ ├── 日常编码 + 轻量 AI 辅助                      │
│ ├── Inline Assist：行级快速修改                   │
│ ├── Agent 面板：中等复杂度的对话式编码             │
│ └── 快速问答、代码解释、小重构                     │
├────────────────────────────────────────────────┤
│ Claude Code（终端）                              │
│ ├── 复杂功能开发（多文件、架构级变更）              │
│ ├── Plan 模式：先规划再执行                        │
│ ├── Agent 模式：委派子任务                        │
│ ├── 自定义命令：/boot /evolve /review             │
│ ├── Hook 自动化：审查、格式化、安全检查             │
│ └── 项目配置管理：CLAUDE.md、Rules、Memory         │
└────────────────────────────────────────────────┘
```

### Phase 2：Prompt Engineering 深度掌握（第 3-4 周）

#### 2.1 Prompt 核心原则

```
好的 Prompt = 上下文 + 目标 + 约束 + 示例 + 输出格式

❌ 坏的 Prompt：
"帮我写个表格组件"

✅ 好的 Prompt：
"在 src/components/ 目录下创建一个 UserTable 组件：
- 使用 Vue3 Composition API + TypeScript
- 基于 Element Plus 的 ElTable 封装
- 支持分页、排序、筛选
- 列配置通过 props 传入，类型为 TableColumn[]
- 支持行选择（多选），选中项通过 v-model 绑定
- 参考 src/components/BaseProTable/ 的代码风格和模式"
```

#### 2.2 Prompt 模式库

| 模式 | 适用场景 | 模板 |
|------|----------|------|
| **需求→代码** | 新功能开发 | 描述需求 + 技术栈 + 约束 + 参考代码 |
| **代码→解释** | 理解陌生代码 | 粘贴代码 + "解释这段代码的逻辑和设计意图" |
| **代码→优化** | 性能/质量改进 | 粘贴代码 + "找出性能瓶颈并优化" + 具体指标 |
| **代码→测试** | 补充测试 | 粘贴代码 + "为这个函数写单元测试，覆盖边界情况" |
| **错误→修复** | Bug 修复 | 错误信息 + 相关代码 + 预期行为 |
| **重构→方案** | 代码重构 | 粘贴代码 + "重构目标" + "不改变外部行为" |

#### 2.3 高级技巧

1. **上下文管理**
   - 善用 @ 引用文件，给 AI 足够上下文
   - 长对话时主动总结，避免上下文污染
   - 关键决策点要求 AI 解释推理过程

2. **分步引导**
   - 复杂任务拆分为小步骤
   - 每步验证后再继续
   - "先给我方案，我确认后再实现"

3. **质量把控**
   - 要求 AI 解释关键设计决策
   - 让 AI 自己审查生成的代码
   - 对 AI 输出保持质疑，不盲信

**实践练习**：
```
1. 用 3 种不同 Prompt 写同一个组件，对比质量
2. 建立自己的 Prompt 模板库（存在 .claude/commands/ 中）
3. 练习"需求→方案→实现"的分步工作流
```

### Phase 3：AI 辅助代码审查与质量保障（第 5-6 周）

#### 3.1 AI 辅助 Review 流程

```
代码审查流程：
1. 写完代码 → AI 初审（bug、安全、性能）
2. AI 发现的问题 → 人工判断是否有效
3. 修复后 → AI 复审
4. 确认无误 → 提交 PR
```

#### 3.2 审查维度

| 维度 | 审查重点 | Prompt 示例 |
|------|----------|-------------|
| **正确性** | 逻辑错误、边界情况 | "检查这段代码是否有逻辑错误或遗漏的边界情况" |
| **安全性** | XSS、注入、权限 | "从安全角度审查这段代码，重点关注 XSS 和权限控制" |
| **性能** | 不必要渲染、内存泄漏 | "检查是否有性能问题：不必要的重渲染、内存泄漏、大列表" |
| **可维护性** | 命名、结构、复杂度 | "评估代码可维护性，建议重构方向" |
| **一致性** | 风格、模式、规范 | "检查是否与项目中现有代码风格一致" |

#### 3.3 自动化审查配置

利用 Claude Code 的 Hook 机制：
```json
{
  "hooks": {
    "post-commit": "claude review --focus security,performance"
  }
}
```

**实践练习**：
```
1. 用 AI 审查自己过去写的 3 个组件，记录发现的问题
2. 建立团队级的 AI Review 规范文档
3. 配置 Claude Code 的自动审查 Hook
```

### Phase 4：AI 驱动的开发工作流（第 7-12 周）

#### 4.1 完整工作流

```
需求理解
  ↓  AI 辅助分析需求，识别隐含约束
技术方案
  ↓  AI 生成方案，人工评审和调整
代码实现
  ↓  AI 辅助编码，人工审查和调整
代码审查
  ↓  AI 自动审查 + 人工审查
测试验证
  ↓  AI 生成测试 + 人工补充边界
文档输出
  ↓  AI 生成初稿 + 人工润色
部署上线
```

#### 4.2 效率度量

| 指标 | 基线（无 AI） | 目标（有 AI） |
|------|---------------|---------------|
| 需求到上线周期 | 5 天 | 3 天 |
| 代码审查轮次 | 3 轮 | 1-2 轮 |
| Bug 率 | 基线 | 降低 30% |
| 测试覆盖率 | 60% | 80%+ |

#### 4.3 建立个人 AI 工具链

```
我的 AI 工具链：
├── 编码：Claude Code（主力，复杂任务）+ Zed Agent 面板（辅助，轻量任务）
├── 审查：Claude Code /review + Hooks 自动审查 + ESLint + TypeScript
├── 测试：AI 生成测试 + Vitest
├── 文档：AI 生成初稿 + 人工润色
├── 学习：AI 解释代码 + 概念问答
└── 自动化：Claude Code Hooks + Git Hooks
```

## 四、常见陷阱

1. **过度依赖 AI** — 不理解 AI 生成的代码就提交
2. **Prompt 太模糊** — 导致 AI 输出不符合预期，反复修改
3. **不验证 AI 输出** — AI 会生成看似正确但有 bug 的代码
4. **忽略上下文** — 不给 AI 足够的项目上下文，输出脱离实际
5. **盲目追求效率** — 速度快但质量差，得不偿失
