# 前端深度进阶学习路线

> 优先级：⭐⭐ 高
> 时间投入：持续进行，与 AI 学习并行
> 目标：建立不可替代的技术深度，从"会用"到"精通"

---

## 一、为什么 AI 时代更需要技术深度

1. **AI 能写浅层代码**：简单的组件、常规的 CRUD，AI 写得比人快
2. **AI 写不了深层代码**：类型体操、性能优化、架构设计，AI 容易出错
3. **深度是审查的前提**：你不懂，就无法判断 AI 写的代码对不对
4. **深度决定天花板**：技术深度决定了你能解决多复杂的问题

> 核心逻辑：AI 让"会用"贬值，让"精通"升值。

#### 1.2 实战练习

```typescript
// 练习 1：实现 DeepPartial
type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P]
}

// 练习 2：实现路径类型提取
type PathOf<T, Prefix extends string = ''> = T extends object
  ? {
      [K in keyof T & string]: PathOf<T[K], `${Prefix}${Prefix extends '' ? '' : '.'}${K}`>
    }[keyof T & string] | Prefix
  : Prefix

// 练习 3：类型安全的表单 Schema
interface FormSchema {
  name: { type: 'input'; required: true; maxLength: 50 }
  age: { type: 'number'; required: true; min: 0; max: 150 }
  email: { type: 'input'; required: false; pattern: string }
}

type FormValues<S extends Record<string, any>> = {
  [K in keyof S]: S[K]['type'] extends 'number' ? number : string
}
```

### Module 5：架构设计能力（持续提升）

#### 5.1 设计模式在前端的应用

```
常用模式：
├── 策略模式 — 表单校验、权限控制
├── 观察者模式 — 事件总线、状态管理
├── 工厂模式 — 组件动态创建、表单生成
├── 适配器模式 — API 适配、第三方库封装
├── 装饰器模式 — HOC、Mixin、组合式函数
├── 代理模式 — 懒加载、缓存代理
└── 发布-订阅模式 — 组件通信、跨模块通知
```

#### 5.2 组件设计原则

```
核心原则：
├── 单一职责 — 一个组件只做一件事
├── 开闭原则 — 对扩展开放，对修改关闭
├── 接口隔离 — Props 精简，不传无用属性
├── 依赖倒置 — 依赖抽象，不依赖具体实现
└── 最少知识 — 组件不需要知道父组件的内部

组件设计 Checklist：
□ Props 类型是否完整？
□ 事件命名是否语义化？
□ 是否支持插槽/内容分发？
□ 是否有合理的默认值？
□ 是否处理了边界情况？
□ 是否有使用文档和示例？
```

#### 5.3 状态管理架构

```
选型决策树：
简单应用 → Pinia / Zustand
中复杂度 → Pinia + Composables
复杂应用 → 状态机（XState）+ 事件驱动
跨应用 → 微前端状态共享方案

架构原则：
├── 状态最小化 — 只存必要的状态，能计算的不存
├── 状态就近 — 状态离使用它的组件越近越好
├── 单向数据流 — 状态变更路径可追踪
├── 不可变更新 — 避免直接修改状态
└── 副作用隔离 — 异步操作与状态更新分离
```

## 三、学习策略

### 1. 深度优先，广度其次
- 每个模块做到"能讲清楚原理"，而不是"用过"
- 用费曼学习法：学完一个知识点，尝试给别人讲清楚

### 2. 源码阅读
- 选择 1-2 个核心库读源码（推荐 Vue3、Pinia、Vite 插件）
- 不求全读，重点读核心逻辑
- 边读边写笔记

### 3. 造轮子练习
- 实现一个简易版 Vue3 响应式系统
- 实现一个简易版 Virtual DOM + Diff
- 实现一个简易版 Vite 插件

### 4. 与 AI 学习结合
- 用 AI 解释你不理解的源码
- 用 AI 生成练习题
- 用 AI 审查你的实现
