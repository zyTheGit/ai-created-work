# `loop-me`

> **分类**：in-progress（开发中草稿）｜**调用方式**：用户手动调用

- **一句话定位**：通过有状态的 grilling 会话，把用户生活/工作中重复出现的模式访谈成可实施的工作流规格。
- **调用方式**：用户手动调用
- **适用场景**：想识别并设计生活中可委派的重复模式（loop），将其固化为 `workflows/*.md` 中的工作流规格；也可不带参数让 agent 自己去发现值得规范的 loop。
- **核心指令**：运行一个有状态的 `/grilling` 会话，唯一产出是 **workflow** 规格；采用 grilling 纪律（穷追不舍、**每轮一次提出一组问题**、每个问题附推荐答案），随访谈结论创建、编辑、删除规格。核心视角：**loop** 是生活中反复出现的模式（职业、一周、一个早晨、某项重复活动），把生活看成环环相扣的 loop 才能看出哪些活动足够可预测、因而值得**委派**；**workflow** 是某个 loop 的规格，你是在 loop 上运行 workflow。共享词汇只在工作流需要时使用，绝不是清单，且**不强制任何结构**：除非 grilling 证明有必要，工作流不需要 AI、不需要 checkpoint、不需要 schedule。词汇：**Trigger**（触发方式，event 如新邮件/新 issue，或 schedule 如每天早晨，事件触发通常更高效）、**Checkpoint**（人工介入点，有些工作流完全没有、全自动运行，有些根本不用 AI）、**Push right**（把 checkpoint 尽量往后推，先做最大量的工作，让人类只被问一次、很晚才被问且一切已备好）、**Brief**（checkpoint 呈现给用户的东西：紧凑、可决策的摘要，即产出了什么、为什么、以及一个指向资产本身的下沉链接，绝不是原始输出；审阅速度是硬要求）。**完成定义**：一份规格只有在实施 agent 能一个问题都不问就把它建出来时才算完成，只要还有问题没解决就没完成。工作区：`workflows/*.md` 每份规格一个文件；`NOTES.md` 记录用户世界的原始笔记：他们用的工具、他们处理的渠道、以及他们对两者的自有术语，为空或太薄时先访谈再规范，出现模糊术语就当场打磨成规范词并记录在此。
