# `teach`

> **分类**：productivity（生产力类）｜**调用方式**：用户手动调用

- **一句话定位**：在当前工作区内教用户一项新技能或概念，支持跨会话的持续学习
- **调用方式**：用户手动调用（可带参数：想学什么）
- **适用场景**：用户想要系统性地学习某个主题；希望获得结构化的课程、练习和参考资料。这是一个**有状态**的请求，用户打算跨多个会话学习该主题
- **核心指令**：
  1. **教学工作区**：把当前目录当作教学工作区。**路径锚定**：`./lessons/` 等工作区路径从 `/teach` 被运行的目录解析，只有 `*-FORMAT.md` 链接从该 skill 自己的文件夹解析。学习状态由以下几处承载：
     - `MISSION.md`：用户为什么对这个主题感兴趣，用于给所有教学打底（格式见 `MISSION-FORMAT.md`）
     - `./reference/*.html`：参考材料目录，是课程的压缩精华，学习的原始单元，应是打印效果好、便于速查的漂亮文档
     - `RESOURCES.md`：可探索以获取知识与智慧的资源清单（格式见 `RESOURCES-FORMAT.md`）
     - `./learning-records/*.md`：学习记录，类似软件里的 ADR，记录非显然的教训与关键洞察，命名 `0001-<dash-case-name>.md` 编号递增；用于计算最近发展区（格式见 `LEARNING-RECORD-FORMAT.md`）
     - `./lessons/*.html`：课程目录，命名 `0001-<dash-case-name>.html` 编号递增
     - `./assets/*`：跨课程复用的**组件**
     - `NOTES.md`：记录用户偏好或工作笔记的草稿本
  2. **教学哲学**：深度学习需要三要素：**知识**（来自高质量高可信资源）、**技能**（通过你设计的高相关度互动课程习得）、**智慧**（来自与其他学习者和实践者的互动）。在 `RESOURCES.md` 充实之前，重点应是找高质量资源，**永远不要相信你的参数化知识**。
  3. **Fluency vs Storage Strength**：区分即时提取的**流利度**与长期保持的**存储强度**。流利度会给用户掌握了的错觉，存储强度才是真目标。课程要用"必要的难度"来构建长期记忆：**检索练习**（凭记忆回忆）、**间隔重复**（把练习分散到时间上）、**交错练习**（混练不同但相关的主题，仅用于技能练习）。
  4. **课程设计**：课程是主要产出。每节课是一个自包含 HTML 文件，只教一件范围很窄、与 mission 挂钩的事；应美观（Tufte 风格、清晰易读的排版）、简短、能很快完成（学习者工作记忆很小），并给用户一个可累积的实在收获，且落在用户的最近发展区内。尽量用 CLI 命令帮用户打开课程文件。每节课用 HTML 锚点链接到其他课程和参考文档，推荐一份最优质的一手资料供阅读观看，并提醒用户向 agent 追问（agent 就是老师）。
  5. **组件复用**：`./assets/` 存样式表、小测组件、模拟器、图示助手等。**复用是默认而非例外**：写课前先读 `./assets/`，从已有组件搭；需要新的可复用物时写成组件并链接，**绝不内联**未来课程会重复的代码。共享样式表是每个工作区赢得的第一个组件。
  6. **Mission 驱动**：每节课都要与 mission 挂钩。mission 不清或 `MISSION.md` 未填充时，第一件事是追问用户为什么想学。mission 可能随用户成长而变化，这很正常：更新 `MISSION.md` 并加一条学习记录，**改 mission 前先与用户确认**。
  7. **最近发展区**：用户始终应感到"刚好被挑战"。用户没说具体学什么时，通过读 `learning-records`、结合 mission 判断该教什么来推断，教最相关且落在 ZPD 内的东西。
  8. **知识与技能的分工**：知识部分要降低认知负荷（难度是知识的敌人，它吃掉理解所需的工作记忆），引用外部资源并**密布引用出处**；技能部分要增加"必要的难度"（难度是技能的工具，费力的检索才构建存储强度），通过互动课程、引导用户完成真实步骤清单来教，每种都建立在**反馈环**上，且反馈要尽可能紧、最好自动即时。
  9. **小测出题规则**：小测每个答案的**词数（尽可能字符数也）完全相同**；**正确答案的位置逐题变化**；不要通过格式或顺序给用户任何线索。
  10. **智慧获取**：用户的问题看似需要智慧时，默认姿态是先尝试回答，但最终委托给**社区**（论坛、subreddit、线下课程、本地兴趣小组）。应主动找高声誉社区推荐；用户表示不想加入社区时尊重其意愿。
  11. **参考文档**：建课时同时建参考文档（语法与代码片段、算法与流程图、瑜伽体式、健身动作、术语表）。课程很少被回看，参考文档会。它们应是课程的压缩精华，为速查而设计。**术语表尤其关键**：一旦创建，之后每节课都要遵守它。
  12. **`NOTES.md`**：用户表达教学偏好或需要记住的事时记在这里，便于后续设计课时回看。
