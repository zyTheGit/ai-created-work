# `writing-beats`

> **分类**：in-progress（开发中草稿）｜**调用方式**：用户手动调用

- **一句话定位**：把一堆原始素材组装成"beat 之旅"，逐拍推进文章，每个概念必须先"接地"才能被后续的拍使用。
- **调用方式**：用户手动调用
- **适用场景**：写作的**利用阶段**（exploit）：探索已结束、素材堆已固定，需要以 choose-your-own-adventure 的方式确定一条穿越素材的叙事路径。
- **核心指令**：用户传入（或稍后传入）一份 markdown 原始素材，确认一次文章保存路径并记住它。**beat** 是旅程中的一个动作：设场景、落论点、提问题、插一句闲话、转折视角，只做一件事然后停下，把读者放在下一个拍能 pivot 的位置；大小随需要而定（一句话、一小段、或作为独立小品的多段），若某个"拍"需要五段加三个小标题，那是两拍粘在一起，拆开。**Grounding** 是核心约束：每个**概念**都必须先接地：要么**前置概念**（读者开篇就自带，一开始固定），要么**已引入**（某个拍建立了它，此后对后续所有拍都算接地）。没接地的概念不可使用；单位是概念而非词语，一拍可能在没有术语的情况下就用上了读者缺乏的想法。每拍身兼两职：**要求**已接地的概念，同时**接地**新概念，要维护一份"目前已接地"清单，每落一拍就更新。流程：①先与用户确定前置概念；②从素材中写 2-3 个候选**起始拍**，每个是进入文章的不同入口，各自只能依赖已接地概念并注明它接地了什么，写入文章文件前先给用户看，用户选一个后**预览这一选择会解锁哪些拍**，像让用户朝路径下方瞥一小段；③只把用户选中的那一拍写入文章文件，写完停下；④从磁盘重读文章文件，再提供 2-3 个候选**下一拍**，方向各不相同，但都必须从当前已接地集合可达，并注明各自接地什么；⑤循环至旅程自然结束。素材是采石场，可改写、拆分、重组、引用，文章在旅程完成时结束而非素材用完时，剩下没用上的片段是正常的。写作节奏：一次只追加一拍、绝不提前写；每次写入前从磁盘重读文件，绝对保留用户编辑；用户大幅改了前一拍就让它影响后续；用户说"重写那一拍"或"回去换第 3 拍"就地改、其余不动。
