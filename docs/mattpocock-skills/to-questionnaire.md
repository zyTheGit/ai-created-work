# `to-questionnaire`

> **分类**：productivity（生产力类）｜**调用方式**：用户手动调用

- **一句话定位**：将用户无法独立回答的决策转化为一份结构化问卷，发给唯一知情者填写
- **调用方式**：用户手动调用
- **适用场景**：用户需要向他人（同事、客户、领域专家）异步收集信息以推进决策时，或约个会一起填。接收者持有用户缺乏的知识，问卷把它从接收者那里取出来。在 `ask-matt` 中被定位为 `/grill-me` 的**反向操作**（ grill 的是别人而不是自己）
- **核心指令**：**访谈"发送"而非"主题"**。普通 grilling 会拷问主题，而这里主题恰恰是用户答不了的，所以只问用户关于**发送**的事（这他们总能回答）：问卷发给谁、需要拿回什么。文档里的问题则瞄准接收者所知与用户所需之间的**差距**。
  1. **发给谁？** 用一轮交流问清接收者的角色、专长和与用户的关系。这决定问卷的语气和需要携带多少上下文。完成标准：知道接收者是谁、以及他们知道什么用户不知道的东西。
  2. **需要拿回什么？** 用一轮交流问清用户无法独自解决、需要从这个人那里得到的具体决策或事实。完成标准：拿到一份具体清单，写清用户最终必须能做什么或决定什么。
  3. **写问卷**：按下面的文档结构，针对第 1–2 步得出的差距起草问题。写入当前目录的 `to-questionnaire-<slug>.md`（slug 取自主题）并报告路径。完成标准：文件存在，且用户在第 2 步点名的每一项都被某个问题覆盖。
- **文档结构**：把文档框定为一份**发现式问卷**（用户缺上下文，接收者有）。问题按**最重要在前**排序，因为异步意味着你可能只拿到一轮。问题超过 handful 就按主题归到 `##` 标题下。模板：
  ```
  # <问卷标题>

  **Purpose:** 这份问卷为何存在、押在上面的决策是什么。

  **From:** <用户>，**To:** <接收者>，**How your answers will be used:** <答案去向>

  ## Context
  一段话，给一个不在用户脑子里的接收者定向。够答好就行，不要一页。

  ## How to answer
  截止时间与大致工作量。部分回答和"我不知道"都有用：不确定的地方标注出来，不要跳过。

  ## <主题标题>
  每个主题一个 `##` 段，段内问题最重要在前。每个问题只有一个点子，绝不复合；
  问题正下方直接跟一个答案占位；只在问题可能被误读或招来敷衍答案时，
  补一行 _why this matters_。

  ### <问题>
  _Why this matters: ..._

  >

  ## Anything else?
  收尾的兜底问题：我们没问到但你应该知道的还有什么？
  ```
