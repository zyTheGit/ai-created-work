# `writing-for-agents`

> **分类**：productivity（生产力类）｜**调用方式**：模型自动调用

- **一句话定位**：写给 agent 看的文档的写作参考手册：用一套可预测性杠杆让 agent 每次都走同一个**过程**
- **调用方式**：模型自动调用（v1.2.0 由 `writing-great-skills` **更名并重构**而来）
- **适用场景**：创建或编辑 skill，或修改 `AGENTS.md` / `CLAUDE.md` 时。参考范围已从"只讲 skill"扩展到**agent 会消费的任何文档**：skill、`AGENTS.md`/`CLAUDE.md`、被指针引到的文档。包装不同，写作相同
- **配套文件**：写的是 skill 时，另读 [`SKILL-MECHANICS.md`]（frontmatter、调用方式选择、router 技能）
- **核心指令**：
  1. **上下文指针（context pointer）**：agent 上下文中持有的一份引用，指名某份不在上下文中的材料，并编码触达它的条件。skill 的 description 是一个，`AGENTS.md` 里指名某文档的一行是同一个对象。**指针的措辞**（而不是它的目标）决定 agent 何时触达材料、以及多可靠。一个"必须有"的目标配一个弱措辞的指针是一个**方差 bug**：先磨措辞，磨不动了才把材料内联。指针做两件事：说明材料是什么，列出应触达它的**分支**（分支是文档处理的一个 distinct 情形，不同运行走不同路径）。常驻指针的每个词每轮都要付费，所以它比正文更该被修剪：**前置领头词**、**一个分支一个触发词**（给同一分支改名的同义词是一个分支写了两遍，合并）、**砍掉正文已承载的身份信息**。
  2. **两种负荷**：每加一份文档或指针都花掉两种预算之一。**上下文负荷**是常驻材料对 agent 窗口的开销（`AGENTS.md` 一行、skill description，每轮都在上下文里，不管是否触发都在花 token 和注意力）。**认知负荷**是对人的开销（有哪些文档、各自何时伸手）。**人是索引**。它不是要最小化的成本，而是人类主体性的代价：在人的判断重要处花它，在不重要处移除它。只经指针触达的材料以指针自身那一行为代价逃过上下文负荷；完全没有指针的材料完全骑在认知负荷上。
  3. **信息层级**：文档由两类内容构成：**步骤**（agent 执行的有序动作）和**参考**（按需查阅的定义、规则、事实）。二者可自由混合。核心决策是每块材料放在**信息层级**（按 agent 多迫切需要材料排序的梯子）的哪一级：
     1. **文件内步骤**是首要一级：agent 按序做什么。
     2. **文件内参考**按需查阅。常常是一个合理平级的同侪集合（一份审查的全部规则在同一级），这是好安排，不是坏味道。
     3. **披露参考**被推到单独文件，由上下文指针触达，只在指针触发时加载。范围从同文件夹的兄弟文件一直到完全外部、任何文档都能指向的参考。
     往下推太少顶层会膨胀；推太多会把 agent 实际需要的材料藏起来。这个张力就是全部决策。
  4. **渐进披露（progressive disclosure）**：沿梯子往下走（移出主文件、藏到指针后面）的动作，让顶层保持可读。它 primarily 不是 token 优化，而是层级受保护的方式。**分支**是最干净的披露测试：内联每个分支都需要的东西，把只有部分分支会触达的东西推到指针后面。文档有步骤时，**本该披露的文件内参考会把步骤埋起来**，让注意它们变成抛硬币。这是方差杠杆，不只是可读性杠杆。
  5. **共置（co-location）**：梯子的文件内伙伴。梯子决定一块材料**往下走多远**，共置决定它到了那级之后**旁边放什么**。把一个概念的定义、规则、注意事项放在同一个标题下，而不是散落各处，这样读一部分能把它的邻居一起带来。测试：文档读起来应像是**为 agent 写的文档**。（与重复不同：重复是在两处说同一个意思；散落是把一个意思碎成多片。）
  6. ** sprawl（膨胀）**：这里的失败模式是文档单纯太长，即便每行都是活的和唯一的。注意力在过量中变薄，多出的每一行都是又一行要维护相关性的。解药是梯子：把参考披露到指针后面，按分支或序列切分，让每条路径只带它需要的。
  7. **步骤与完成标准**：每个步骤都收在一个**完成标准**上（告诉 agent 工作做完的条件）。两个属性让它成为杠杆：
     - **清晰度**：agent 能否区分做完与没做完？模糊的边界（"达成理解"）会招来**过早完成**：在工作真正完成前就结束步骤，注意力滑向"处于完成状态"。前面仍可见的步骤（**完成后步骤**）提供拉力，标准的清晰度是阻力。按序防御：**先磨边界**（局部且便宜）；只有当它本质模糊**且**你观察到抢跑时，才通过切分序列把后续步骤藏起来。隐藏只在跨越真实上下文边界时有效（交接或 subagent 派发；内联调用会把后续步骤留在上下文里，什么都清不掉）。
     - **要求度**：它要求多少。"每个改动的模型都被交代"比"产出一份变更清单"更能迫使做透。要求度驱动**跑腿活**（agent 在工作内部做的挖掘，潜伏在措辞里而不是写成独立步骤），且它不受步骤约束："每条规则都应用"约束一份平铺参考，正如"每步都做完"约束一个序列，这就是一份纯参考文档如何仍然扛着一条穷尽性标准。
     最强的完成标准同时**可检验**且**穷尽**。
  8. **何时切分**：切一份文档为两份要花掉两种负荷之一，所以只在切口划得来时才切：
     - **按序列**：切在一段步骤上，当完成后步骤诱惑 agent 草率对待眼前这一步时。让它们不在视野内能驱动更多跑腿活。警惕反面：合并序列会把每一步的后续步骤暴露给跟着它的东西，招来过早完成。
     - **按调用方式**：skill 专属，见 `SKILL-MECHANICS.md`。
  9. **领头词（leading word）**：一个已活在模型预训练里的紧凑概念，agent 运行文档时用它思考（_lesson_、_fog of war_、_tracer bullets_）。作为 token 重复而不是作为句子重复，它会积累一个分布式定义，并用最少的 token 锚定整片行为区域，招募模型已持有的先验。自造词只要你定义清楚也能用，但**编造的词招募不到先验**：你付的是定义 token，而预训练给的词免费；先伸手够已有的词。
     它锚定两次。在正文里是**执行**：词每次出现，agent 都伸手够同一行为，在平铺参考里它把注意力聚焦到一类要找的东西上。在指针里是**调用**：当同一个词活在你的提示词、你的文档和你的代码库里，agent 会把那份共享语言与材料关联起来，更可靠地触达它。
     猎求用领头词重构的机会。三处拼写出来的三元组、花一句话gesture 一个想法的指针，每一处都是哀求塌缩成单个 token 的段落：
     - "fast, deterministic, low-overhead" → _tight_（一个 _tight_ 循环）
     - "a loop you believe in" → _red_，把模糊的门变成二元的可观测状态（循环在 bug 上变 _红_，或者没有）
     你赢两次：更少 token，以及一个更锋利的钩子让 agent 挂住思考。**假定每份文档都扛着领头词能退休的复述。去找出来。**
  10. **否定（negation）**：紧邻这个杠杆的失败模式：用禁止来转向会把被禁的行为拖进上下文，让它**更**可用而非更少。别想大象，大象就成了全部；否定是个弱修饰语，被强激活的概念冲垮，于是禁令有一半被读成"去做那件事"的指令。**提示正向的**：陈述目标行为（"写单行注释"），让被禁的那个根本不被说出口。一条禁止只在它是你无法正向表述的硬护栏时才配占位；即便如此，也要配上正向目标，让注意力落在该做什么上。
  11. **修剪**：
     - 每个意思保持**单一事实来源**：一个权威位置，改行为是一处编辑。**重复**（同一意思在多处）花维护和 token，并把一个意思在梯子上的显著性抬到超过它的真实等级。（领头词的反面：领头词是故意重复一个 token，从不重复意思。）
     - **环境也是事实来源**（`package.json` 脚本、配置文件、目录布局、`--help` 输出），复述它的文档是一份**缓存**：一次查找的副本，只在查找很贵时才配得上它的加载。缓存 agent 靠看找不到的东西：不成文的约定、一个选择背后的理由、没有配置会承认的坑。把"一文件一命令"的查找留给环境，那里它们不会过期。
     - 逐行检查**相关性**：它是否仍与文档所做的事有关？一行会因从不与任务相关（纯阐述，或一个本该被披露的分支）或随它描述的行为/世界变化而过时。更短的文档更容易保持相关。没有修剪纪律，默认结局是**沉积**：层层陈旧沉积下来，因为添加感觉安全、移除感觉冒险，直到你必须钻透它们才能找到还活着的。
     - 逐句猎**空操作（no-op）**：一条模型默认就会遵守的指令，付了加载费却什么都没说。测试（相对默认它是否改变行为？）是**模型相对**的而非读者相对的：两个人对某个空操作有分歧，是对默认有分歧，靠运行文档来解决，不靠辩论。句子不达标时**删掉整个句子**，而不是从里面修剪字词。这个测试同样给领头词分级：一个弱到打不赢默认的词（agent 已经够 thorough 时的 _be thorough_）是空操作，解药是更强的词（_relentless_），不是换技巧。
- **配套分支 `SKILL-MECHANICS.md`**（v1.2.0 新增，承载 skill 专属机制）：
  - **调用方式二选一**，交换的是那两种负荷。**模型自动调用**的技能保留 `description`，agent 能自主触发它，其他技能也能触达它；你照样能敲它的名字（模型调用总是**包含**用户触达，description 只会增加 agent 发现，从不拿走人的）。description 是技能的顶层上下文指针，被迫常驻：以永久上下文负荷换可发现性。内容全是参考的模型自动技能也是共享参考的一个归宿：另一个技能能调用它，所以多个技能都需要的参考住在一处。机制：省略 `disable-model-invocation`，写一段面向模型、携带触发分支的 description。**用户手动调用**的技能把 description 从 agent 的触达中剥掉：只有人敲名字能调用，没有其他技能能。零上下文负荷，但花认知负荷：**你是那个必须记住它存在的索引**。机制：设 `disable-model-invocation: true`，`description` 变成面向人的一行摘要，触发清单被剥掉。
  - **选择规则**：只在 agent 必须自己伸手够到它、或另一个技能必须够到它时才选模型调用。如果它只靠手触发，就做成用户手动调用，不付上下文负荷。
  - **共享参考的归属**：两个用户手动技能都需要的共享参考无处可放（没有 description，谁也触发不了谁）。把它推到技能系统之外的普通文件：任何技能都能指向的外部参考。
  - **按调用方式切分**：当你有一个**distinct 领头词**应该独立触发它时（一个你真的会在提示词里用的触发词），或另一个技能必须够到它时，切出一个模型自动技能。你为新的常驻 description 付上下文负荷，所以那份独立触达必须划得来。
  - **Router 技能**：当用户手动技能多到你记不住，堆积的认知负荷由一个 **router 技能**治好：一个用户手动技能，指名其他技能以及各自何时伸手，让人只需记一个技能。它**只能提示，绝不能触发**：用户手动技能没有 description，除了人没有东西能触达它们。
