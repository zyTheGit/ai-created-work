# `grilling`

> **分类**：productivity（生产力类）｜**调用方式**：模型自动调用

- **一句话定位**：针对某个计划、决策或想法，对用户进行持续不断的深度追问，按"设计树 + 前沿 + 轮次"组织
- **调用方式**：模型自动调用
- **适用场景**：用户想要压力测试自己的思考；使用任何"grill"相关触发短语时。措辞已泛化，不再局限于软件计划（"this plan" → "this"，"enact the plan" → "act on it"），可作为对任何计划、决策或想法的压力测试
- **核心指令**：
  1. **把访谈映射为设计树**：每个决策分支到挂在它下面的决策。
  2. **按轮次推进**：**前沿（frontier）** 是前置条件已定的全部决策，即不必猜测未听到的答案现在就能问的问题。**一轮问完整个前沿**：每个问题编号并给出推荐答案，然后等用户答完再进下一轮。
  3. **轮格式固定**：
     ```
     ❓ **Q1** - **<问题标题>**: <问题正文，可含多段与多选>

     ➡️ <你的推荐答案>

     ---

     ❓ **Q2** - ...
     ```
     推荐答案单独占一行 `➡️`，与问题视觉分离；连续问题之间用水平分隔线 `---`，不要连在一起。
  4. **把问题措辞改造成"是"即接受推荐**：让用户能用一个"是"来认可你的推荐答案。
  5. **重算前沿**：每轮回答都会重塑决策树，已定的决策把前沿向外推、解锁依赖它的问题。答案依赖本轮仍未关闭的问题的那个问题属于**更晚的一轮**。
  6. **找事实是你的活，不是用户的**：前沿问题需要环境中的事实（文件系统、工具等）时，派 sub-agent 去查，不要问用户你自己能查到的东西。但**不要阻塞**：正在进行的探索是一个未定的前置条件，只有依赖它的问题等 sub-agent 汇报，前沿其余问题现在就问。**决策权属于用户**：每个决策都要摆给用户并等待。
  7. **收尾条件**：前沿为空时会话结束，设计树每个分支都走过，没有任何东西被默默假定。在用户确认达成共识之前不要行动。
