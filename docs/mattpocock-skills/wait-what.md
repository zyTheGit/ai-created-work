# `wait-what`

> **分类**：productivity（生产力类）｜**调用方式**：用户手动调用

- **一句话定位**：模型话太多/没讲懂时的单字纠正："等等，重讲一遍"
- **调用方式**：用户手动调用（v1.2.0 新增）
- **适用场景**：某条消息**没有落地**的那一刻就敲它，agent 会重新讲一遍
- **核心指令**：全文只有一句："等等，我不明白你讲到哪里了。重讲一遍：给我一点上下文，用 ASD-STE100 简化技术英语讲，并使用 `GLOSSARY.md` 里的统一语言（仓库有多个上下文时，跟随 `GLOSSARY-MAP.md` 找到对应的那个）。"
- **设计意图**（理解它为什么只有三行）：
  - **机制就是名字本身**。讲求简洁的技能失败的方式是膨胀：400 行的技能依然会让模型啰嗦。所以这个技能是一个精确的领头词，别无他物。
  - **描述输出的名字会反效果**。`/tldr`、`/no-fluff` 这类名字让模型砍词，反而让你更听不懂；命名**听者的状态**则同时要到两半：更少的词，和你缺失的上下文。
  - 它复用了你全局 `CLAUDE.md` 里已有的领头词，让技能、`CLAUDE.md` 和每份 `GLOSSARY.md` 伸手够向同一批 token。
- **边界**：它只修一条消息，不预防下一条。术语混乱的根本解药是事先用 `/grill-with-docs` 建立共享语言；`wait-what` 是你还没有那种语言时伸手够的东西。
