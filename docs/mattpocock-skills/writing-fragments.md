# `writing-fragments`

> **分类**：in-progress（开发中草稿）｜**调用方式**：用户手动调用

- **一句话定位**：写作的**探索阶段**，通过穷追不舍的访谈从用户身上挖掘原始片段（fragment），此阶段不施加任何结构。
- **调用方式**：用户手动调用
- **适用场景**：写作初期有大量想法但尚未定型，需要自由探索、积累素材片段，为后续 exploit 阶段（`writing-beats`/`writing-shape`）准备原料堆。
- **核心指令**：这是纯 **explore**：扩大"可能写出什么"的空间而不对结构作出承诺。承诺属于 *exploit*，是另一个技能的职责。运行一个产出片段的 grilling 会话，就用户想写的任何话题 relentlessly 访谈；在此施加阶段划分、大纲或文章结构都属于越界。随着片段从对话双方浮现，把它们追加进单个 markdown 文件；用户没给路径就问一次并在此后记住。从用户开口的第一句话（含初始 prompt）就开始捕获片段。首次写入时在顶部放唯一一个 H1 工作标题（之后可改），除此之外什么都不放：无元数据、无目录、无日期。**片段**是任何可能存活进最终文章的文本，只需**作者自己能读懂**（作者知道它是什么意思），不必定义术语、也不必让冷读者看懂，标准是"这是一段好文字吗？"而非"这是一个自洽论证吗？"片段刻意保持异质：一句想在某处投放的锋利句子、带一行论证的判断、小故事（一件事、一段代码、一个场景、一个类比）、半成形的想法（"关于 X 有多像 Y，以后再想"）、一句引文或对话或旁听到的话、凭感觉聚在一起的相关观察清单、一句抱怨/忏悔/ punchline，以及最有价值的**主导词（leading word）**：一个能让整篇文章挂在上面的紧凑隐喻或新造词（用一个术语命名整个想法，如同 _tracer bullets_、_fog of war_ 命名一整套模式）。主导词是最值得落下的片段、是承重的：explore 阶段命名对了，它会在之后塑造结构、过渡和标题，在整个 exploit 阶段持续带来回报；当对话围着某个反复出现的想法打转时，要推动为它造一个词。小说家的日记是范本：多年无结构的观察记录，日后被开采成素材，片段就是观察。文件格式：片段之间用水平线（`\n---\n`）分隔，正文内无标题、无标签、除追加顺序外无排序。写作节奏：静默追加，不为每个片段征求许可，顺带提一句加了什么（"adding that"），不要用保存对话框打断对话；每次写入前从磁盘重读文件，用户可能在中途编辑、重排或删除了片段，必须保留其改动，绝不覆盖整份文件，只追加（或应用户要求就地改某个片段）；用户随时可以说"cut the last one"、"rewrite that one sharper"、"merge those two"，这些话都是一等指令。
