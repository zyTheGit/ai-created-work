## 二、v1.2.0（2026-08-05）：破坏性变更集中版

### 2.1 新增技能（3 个）

| 技能 | 分类 | 调用方式 | 说明 |
|---|---|---|---|
| `wait-what` | productivity | 用户手动 | 模型话太多时的"等等，重讲"。只有三行：补一点上下文 + ASD-STE100 简化技术英语 + `GLOSSARY.md` 里的统一术语。设计意图是**用命名描述听者状态**而不是描述输出（`/tldr`、`/no-fluff` 这类名字会让模型砍词，反而更听不懂）。它只修一条消息，不预防下一条 |

| （`writing-for-agents` 由更名而来，见 2.4） | | | |

### 2.2 升桶与调用方式变更（2 个）

### 2.4 重命名（1 个，破坏性，无别名）

|---|---|---|
| `writing-great-skills` | `writing-for-agents` | 参考范围从"只讲 skill"扩展到"agent 会消费的任何文档"（skill、`AGENTS.md`/`CLAUDE.md`、被指针引到的文档）。同时 `GLOSSARY.md` 并入 `SKILL.md`（一个术语一处权威论述，`_Avoid_` 同义词表和独立的 Predictability 定义被删），纯 skill 机制（frontmatter、模型/用户调用之分、router 技能、调用切分）移到新的 `SKILL-MECHANICS.md`。**必须用新名重装，旧名直接消失** |

### 2.5 重大重写（5 个）

- **`prototype`**：围绕两个理念重塑：演示物是**单个可分享的 HTML 文件**，原型是**一手资料**。逻辑分支现在产出的是一个自包含文件（纯 HTML/CSS/JS，无构建、无服务器），非开发者双击就能打开，用自己的领域语言驱动它：一个带标签的状态面板、始终可用的自由操作按钮、一组分标签页的**引导式演练**（每个是一个场景，下方列出要按的按钮顺序）。可移植的纯逻辑模块仍然可以提升进真实代码，HTML 外壳才是可丢弃的。"可丢弃"不再等于"删掉"：原型作为可运行的证据留在从 main 切出的 throwaway 分支 `prototype/<name>` 上，并在实现 issue 上留一个上下文指针。答案（结论 + 问题）仍然落在 issue/ADR/commit 里。
- **`wayfinder`**：把工单命名为**决策工单（decision ticket）**，并用 subagent 烧掉调研工单。此前人们反复把 wayfinder 工单读成普通实现工单，现在描述和开头就引入这个词。调研工单不再留给另一个会话手动启动：创建完工单后，绘图会话为每个调研工单各拉起一个 `/research` subagent 并行烧掉，结论留在 throwaway 的 `research/<name>` 分支上并加指针。调研工单是"一次会话一个工单"的唯一例外。
- **`grilling`**：从"一次一问"改为**按轮次问前沿**。先了解决策树，把整个前沿（前置条件已定的全部问题）作为一轮编号问题一次问完，再从用户的回答重算前沿问下一轮。同样 13 个问题约 3 轮就问完。环境能回答的事实派给后台 subagent，调研不阻塞轮次。措辞也泛化了（"this plan" → "this"，"enact the plan" → "act on it"）。`grill-me`、`grill-with-docs`、`triage` 同样改为按轮次。
- **`ask-matt`**：新增**阶段边界决策树**。一个 phase 是会话内的一块工作（grilling、实现、QA），两个 phase 之间的边界就是你决定怎么处理已积累的上下文的地方。原来的两条"Crossing sessions"被替换成按顺序给出五个选项的决策树：**continue → `/clear` → `/handoff` → subagent → `/compact`**，理由写在新的 `PHASE-BOUNDARIES.md`。三个修正：`/handoff` 被高卖了（它很窄，只在需要**搬运**上下文时才用：换 harness、换目录、交给同事、phase 中途 fork 出的支线任务，它买的是可移植性）；`/compact` 是默认而非首选（它在树的最底部，在四个更便宜或更精确的选项之后，一上来就 compact 会得到一个对摘要抹平的东西自信地犯错的会话）；**continue** 和 **subagent** 两个分支此前完全缺失。智能区上限从约 120k 更新为约 150k tokens。另外补上了此前完全没进路由器的 `/grilling` 和 `/resolving-merge-conflicts`，并让 `grill-me` 与 `grill-with-docs` 按"你是否在一个工作目录里"分流。
- **`setup-matt-pocock-skills`**：更友好，并让本地 markdown tracker 与当前 spec 对齐。triage labels 只在装了 `triage` 技能时才问，且合并为单个"保留默认 triage labels 吗"的推荐项；外部 PR 不再是设置问题（模板仍带该开关，默认关）；领域文档默认单上下文不再询问，只在仓库呈现 monorepo 信号时才提供多上下文；**本地 markdown 工单改为一文件一工单** `.scratch/<feature>/issues/<NN>-<slug>.md`（绝不再是单个合并的 `tickets.md`），spec 文件叫 `spec.md` 而非 `PRD.md`。

### 2.6 其他变更

- **打包为 Claude Code 官方插件**：`claude plugins install mattpocock-skills`（或会话内 `/plugin install mattpocock-skills`），无需先添加 marketplace，官方 marketplace 默认已配置。插件元数据在 `.claude-plugin/plugin.json`。`skills.sh` 仍是通用安装器（也是 Codex 等其他 harness 的路径）；原生 Codex 插件暂缓，理由见 `.agents/adr/0002-ship-as-a-claude-code-plugin.md`。
- **Codex 元数据**：每个 `SKILL.md` 旁新增 `agents/openai.yaml`（`interface.display_name`、`interface.short_description`），每个用户手动技能标 `policy.allow_implicit_invocation: false`（`disable-model-invocation: true` 的 Codex 对应物），`AGENTS.md` 作为 `CLAUDE.md` 的符号链接加入，让 Codex 读到同一份仓库指令。
- **`improve-codebase-architecture`** 的 Explore 步骤新增 **YAGNI 范围过滤**：不再均匀扫全仓，而是定位到改动真正落地的地方：你指定方向就用你的，否则读最近约 20 条 commit message 把探索偏向活跃路径。没人碰的代码里的深化机会是你永远兑现不了的重构。
- **`to-prd` → `to-spec` 更名收尾**："spec" 成为出货文本里的唯一术语。`to-spec` 开头不再说"你可能把这份文档叫做 PRD"；`code-review` 讲的是来源 issue/spec 而非 issue/PRD；GitHub/GitLab tracker 模板改说 "Issues and specs for this repo live as GitHub/GitLab issues"（此前本地模板更新时漏了它们，导致陈旧术语渗进每个用模板初始化的仓库）；`docs/engineering/research.md` 里指向已失效 slug 的链接修正。

## 五、v1.3.0（2026-09-29）

### 5.1 新增技能（3 个，全部升入 engineering）

| 技能 | 调用方式 | 说明 |
|---|---|---|
| `implement-spec` | 用户手动 | 一次跑完整个 spec。把工单读作**任务图**，在就绪的**前沿**上于各自 worktree 中运行 implementer subagent，全部落到**一条集成分支**，最后以 `code-review` 收尾。目标现在是集成分支而不是 PR：只有当 issue tracker 通过 PR 关闭工作、或你明确要求时才开草稿 PR，且必须在第一次合并之后（没有领先 main 的提交的分支开不了 PR）。每个 implementer 会确认自己的 worktree 基于集成分支、用 `tdd` 构建自己的工单、并在报告完成前把集成尖端合并进自己的分支，使每次合并都是快进 |
| `pr` | 模型自动 | PR 正文应有的形状：摘要用**能讲清改动的最小可视化**（伪代码、调用树、文件树、Mermaid、diff），然后是证明它生效的前后证据，最后是**合并危险性判断**（单向门还是双向门 + 爆炸半径）。摘要可视化改编自 Dex Horthy 的 `show-me`，在技能的 `CREDITS.md` 中署名 |
| `retro` | 用户手动 | 回顾一次编码会话，建议改的是 **agent 的环境而非代码**：导航指针、自动化检查、编码规范、steering 文件、工具经济性、信息可达性。它先给每条编码规范发现分类：机械性违规应得到确定性检查（linter 规则、pre-commit hook 或 CI job），`CODING_STANDARDS.md` 只留给真正的判断调用。一个完全没有护栏的仓库本身就是一条发现 |

`ask-matt` 中：`implement-spec` 是逐工单 `implement` 的并行替代路线，`pr` 是 PR 正文收尾路线，`retro` 是主流程 `code-review` 之后的最后一步。

  > 值得注意的是它在 v1.2.0 才刚刚被加进 `ask-matt` 路由器，一版之后又被移除。

### 5.3 全局重命名：`CONTEXT.md` → `GLOSSARY.md`

v1.3.0 覆盖面最广的一次改动。`CONTEXT.md`/`CONTEXT-MAP.md` 这套领域文档约定更名为 `GLOSSARY.md`/`GLOSSARY-MAP.md`，涉及 **11 个技能**：

`domain-modeling`、`grill-with-docs`、`improve-codebase-architecture`、`setup-matt-pocock-skills`、`triage`、`tdd`、`diagnosing-bugs`、`ask-matt`、`codebase-design`、`wait-what`、`pr`

- **`wait-what`**：仓库以 `GLOSSARY-MAP.md` 索引多个上下文时，跟随它找到对应的 `GLOSSARY.md`，而不是固守单个根 `GLOSSARY.md`。

## 九、对本目录使用者的实际影响

如果你此前照本目录的旧版文档配过仓库，需要手动处理的事项按重要性排列：

1. **`git mv CONTEXT.md GLOSSARY.md`**（v1.3.0）：影响最大。技能从此只找新名字，旧文件会被完全忽略。多上下文仓库还要 `git mv CONTEXT-MAP.md GLOSSARY-MAP.md`。
2. **用新名重装 `writing-for-agents`**（v1.2.0），旧名 `writing-great-skills` 直接消失，没有别名。
3. **本地 markdown 工单迁移为一文件一工单**（v1.2.0）：从单个 `tickets.md` 改为 `.scratch/<feature>/issues/<NN>-<slug>.md`，spec 文件叫 `spec.md` 而不是 `PRD.md`。
4. **`to-prd` 的说法彻底废弃**（v1.2.0 收尾），一律说 `to-spec` / spec。
5. **改用插件方式安装**（v1.2.0 起可选）：`claude plugins install mattpocock-skills`，作为托管只读捆绑，替代复制可编辑文件。
6. **删除的技能不要再引用**：特别是 `ubiquitous-language`（→ `domain-modeling`）、`design-an-interface`（→ `codebase-design`）、`qa`（→ `triage`/`to-tickets`）、`request-refactor-plan`（→ `to-spec`/`improve-codebase-architecture`）、`resolving-merge-conflicts`（无替代）。
7. **`ask-matt` 的上下文卫生建议变了**（v1.2.0）：边界处首选 `/compact` 而不是 `/handoff`；`/handoff` 只在需要搬运上下文时用；智能区上限按 150k 而非 120k 估算。
